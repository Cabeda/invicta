# Model audit and first-failure investigation

Accepted first slice of the [simulation-loop retrospective](simulation-loop-retro-2026-10-29.md). The aim is to select a useful next experiment before another full regional execution. This slice does not deliver a compliant transport proposal or the later search coordinator.

## Public boundaries

- Load one hash-bound execution and its complete scheduled reference from a native folder or the frozen archive. Reject changed evidence. Preserve all 127 workings and 714 designated timing checks for the current 701 study.
- Audit both directions, short workings, route/stop consistency, bus permissions, connectors, stop footprints and geometric review screens. Readiness requires a matching full-service empty diagnostic, without unresolved timetable failures. Geometry thresholds are project review triggers, not surveyed acceptance criteria.
- Block an expensive new run before creating output unless the model is ready and the configuration states a change, prediction and supporting evidence. An explicit empty diagnostic can bootstrap readiness. A bounded prefix or changed vehicle profile cannot supply full-day readiness.
- Check compiled native bus calls, ordinary physical endpoints/departures, passenger/walking counts and pedestrian permissions before execution. Keep missing or disconnected requests as failures.
- Use the same observed native runner for passive and signal-priority trials. Capture bounded samples, first pending-deadline and prolonged-wait states, progress, runtime/source identities and preparation/execution/evaluation/verification timings. Observation must preserve passive native stop calls.
- Explain the first checkpoint failure and its previous timing interval, separating inherited from locally added delay. Report unclassified causes when stop output or queue context cannot establish causality.
- Reproduce a prefix from its original inputs and warmup, within one simulated hour and a 120-second native wall budget checked at each step. Verify completed stop-call equivalence for the unchanged control. An explicitly labelled vehicle-behaviour sensitivity is diagnostic evidence, never a street intervention or full-service qualification.
- Inspect saved native states without executing a simulation step or changing source files. Show a bounded selection of bus/leader/foe contexts.
- Provide compact CLI summaries and machine-readable reports. Retain native evidence for both the first Codiceira–Ermesinde failure and final unfinished-trip queues. No new numerical result inherits the existing animated replay.

Acceptance extends the pre-agreed line/evidence-loading and complete-trip evaluation seams. Existing browser share/replay/export checks remain release gates; this slice does not change those user flows.

## Deferred recommendations

The canonical JavaScript/Python goal interface, automatic search coordinator, content-addressed execution registry, proposal promotion, fleet blocks and reusable multi-line StudySpec remain follow-up work. Public-data calibration gaps remain explicit. A passing synthetic fixture establishes a software success path, not real-world readiness.
