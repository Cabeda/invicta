# Costa Cabral: integrated 3D inspection prototype

Question answered: can the same SUMO scenario be inspected inside the bilingual proposal in 3D, with a useful street-level camera, without a separate simulator or hosted map service?

**Yes.** The throwaway implementation is integrated into `proposal/index.html` on branch `prototype/costa-cabral-access`. It displays the existing uncalibrated model; it does not establish safe clearances, actual bus punctuality or a surveyed digital city.

## Open and operate

Serve the existing prototype directory, then open:

`http://127.0.0.1:8765/proposal/index.html?dimension=3d&camera=conde&view=restricted&speed=5`

Alternatively choose **Explore in 3D / Explorar em 3D** above the replay. All existing demand, policy, junction, language, timeline and playback controls are shared with 2D.

- **Free orbit:** drag to rotate, scroll/pinch to zoom, right-drag/two-finger pan to move. Baseline/proposal cameras move together.
- **Street level:** camera at 1.7 m; drag to look, use WASD/arrows or the on-screen buttons to move. This is a free inspection camera, with no building-collision detection or simulated pedestrian.
- **Follow a bus:** choose a bus. Both policies follow that same ID at the same simulation time. If it is inactive in one policy, the status states that; choosing a bus can seek to its first appearance in the proposal excerpt.
- Hide buildings for unobstructed geometry inspection; reset the camera or select another junction.
- **Share this view** retains 2D/3D, viewpoint, camera pose, buildings, bus, scenario, policy, time, speed and language. Selection JSON includes the pose too.
- **Record view (WebM)** captures the selected 3D camera(s) with the current scenario/language. The existing captioned MP4 films remain 2D; browser recording is the 3D video path.

## What is rendered

- Lane shapes/widths and junction surfaces from the exact native SUMO network. Baseline and restricted lane IDs/shapes were compared: no geometry differences. Green shows the proposed restricted corridor; centre guides and stop markers are inspection aids, not surveyed markings/platforms.
- Actual seed-17 SUMO trajectories for all three demand cases, baseline and proposal, 08:12–08:24. **721 native one-second frames per clip**, using the original one-second simulation step. Same network, routes and stops; no new traffic assumptions or recalculated headline outcomes.
- Distance interpolation on the same lane follows its polyline. Across lane changes, native neighbouring samples are interpolated. Smoother display is not additional simulation precision.
- Vehicle body dimensions queried through TraCI from the original SUMO 1.28.0 type definitions, including class defaults. The bus is 12 × 2.5 × 3.4 m; the 5 × 1.8 × 1.5 m car is a generic simulator type. These are simple meshes, not surveyed STCP fleet models. The front-bumper position is offset by half the vehicle length to place its body centre correctly.
- **2,089 mapped OpenStreetMap building-way footprints** near the corridor, recovered from the original frozen-input source tiles. None in this extracted set has a usable explicit height tag. Heights use mapped storeys × 3.2 m where present; otherwise illustrative 9 m. Closed building ways only; no complete multipolygon/indoor/facade reconstruction.
- The model is **flat**. Actual hills, bridge elevations, kerbs, sidewalks, street furniture, pedestrian flows, cyclist passing behaviour and sightlines are not validated. Do not interpret overlapping grade-separated roads in the flat view as physical junctions or use the scene for clearance certification.

The original 2D map and MP4s keep four-second samples and enlarged symbols. Their numerical report still aggregates the original three-seed runs; the 3D excerpt uses one seed.

## Code and portable export

- `prepare_3d.py`: freeze mapped context, export network geometry and capture one-second native FCD. Strips statistics writers to preserve original run outputs.
- `data/buildings-3d.json.gz`: frozen extracted footprint context plus original tile hashes and height rules.
- `data/vehicle-dimensions-3d.json`: queried model dimensions and provenance.
- `inspection-assets/`: compressed scene and six replay assets. Network/input hashes and projection metadata retained.
- `inspection-3d.js`: display, cameras and playback only. SUMO remains the simulation engine.
- `vendor/`: pinned Three.js **0.186.1**, OrbitControls and MIT licence. No CDN, API key, remote imagery or hosted terrain service.

Rebuild with `./prototypes/costa-cabral/export-proposal.sh --skip-video`. The command reuses matching captures; original run inputs can be rebuilt with `prototype.sh` if necessary. The frozen building extract avoids depending on ignored raw map tiles for subsequent exports.

The ready-to-host ZIP includes `inspection-3d.js`, `vendor/` and `inspection-assets/` recursively. Upload the whole folder. 3D requires a static **HTTP(S)** host, WebGL2 and a browser supporting `DecompressionStream('gzip')`; it cannot load modules by double-clicking `index.html`. The existing 2D view remains available directly from disk.

## Verification

- Native capture: all **209 completed bus-stop events within the excerpt** matched original IDs, start/end times and stops across six clips (35/39 moderate, 26/40 busy, 31/38 resident-demand; baseline/proposal respectively). Stops continuing beyond the clip end are excluded from that comparison.
- Lane geometry and native vehicle dimensions checked against the source simulation.
- Actual WebGL output visually inspected from an orbit and a bus-following camera. A logarithmic depth buffer prevents nearby road/ground surfaces fighting at district scales.
- Browser checks cover 2D/3D switching, synchronized comparison, bus following, street camera, languages, demand/camera changes, shared state and phone layout.
- A real browser 3D recording produced VP9 WebM at 1920 × 1080. Existing MP4s were retained.

Remaining decision work is in [the project brief](../../docs/PROJECT_BRIEF.md). Local shopper/service access, real traffic, signals and bus operations still require modelling and validation.
