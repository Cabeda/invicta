# Costa Cabral: presentation outputs

The presentation asks whether a restricted two-direction corridor could prioritize buses while preserving resident access and direct junction crossings. It is a proposal for discussion using an **uncalibrated model**. It does not claim observed or guaranteed real-world improvements.

The agreed goal is bus punctuality while catering to residents, shoppers, businesses and everyday services. The bilingual site and films now lead with this goal. The first displayed metric is the existing illustrative final-stop arrival check (no more than three minutes late), with unfinished bus trips counted as failures. Early departures, upstream lateness and shopper/service access still require explicit modelling and validation. Local needs do not automatically grant new vehicle exemptions.

## Delivered outputs

- Portuguese and English MP4s: `proposal/costa-cabral-pt.mp4`, `proposal/costa-cabral-en.mp4`.
- Bilingual interactive website: `proposal/index.html`.
- Integrated 3D inspection: choose **Explore in 3D / Explorar em 3D**, with orbit, street-level and bus-following cameras. See [3D.md](3D.md).
- Ready-to-host archive: `costa-cabral-proposal-site.zip` (generated locally; not versioned).
- Compressed source trajectories: `media/replays.json.gz`.
- Machine-readable film settings and MP4 hashes: `proposal/video-info.json`.

The MP4s are 60 seconds, 1920 × 1080, H.264, 25 fps, with burned-in explanatory text and no audio dependency. The language switch changes the interface and selects the matching MP4/poster.

## Film sequence

| Time | Content |
|---|---|
| 0–7 s | Corridor, proposal and allowed groups. |
| 7–15 s | Two-direction access diagram; direct crossings remain possible. This is schematic, not surveyed engineering. |
| 15–51 s | Synchronized baseline/restricted SUMO trajectories, 08:12–08:24, at 20× simulated time. |
| 51–60 s | Illustrative final-stop schedule check across three seeds, completed-trip bus means as supporting evidence, explicit no-route demand, and validation/trial next steps. |

A persistent label states that the traffic is simulated and uncalibrated. Standardized films use the moderate-demand case; the CLI also accepts another case and junction camera. The video metadata identifies the actual chosen settings, and the website film caption follows that metadata rather than the interactive replay's independently selected case.

## What moves on the map

The replays are generated by rerunning the exact frozen native SUMO network/route/stop inputs with seed 17. They are not a decorative animation or observed GPS. FCD captures vehicle ID/type, x/y, angle and speed every four seconds; playback interpolates between samples. Vehicle symbols are deliberately enlarged so a whole-corridor view is readable.

The added 3D mode uses a separate capture at every native one-second step, plus lane and longitudinal position for interpolation. Vehicle dimensions match the original SUMO type definitions. Its street context uses mapped footprints and estimated heights on a flat network. These are simple geometry models; surveyed kerbs, grades, accessibility and safety are not established. Browser WebM recording can now capture 3D; the prepared MP4 films remain 2D.

There are six replay datasets: baseline and restricted access for moderate demand, heavier through demand and increased resident access. Browser metrics are from the complete original three-seed experiment, not recalculated from the 12-minute excerpt. Some requests have no permitted route or remain unfinished, so completed-trip means cannot be interpreted as an equal-served-demand welfare comparison.

## Website controls and exports

- PT/EN language and film selection.
- Play/pause, timeline scrubbing and playback speed.
- Three precomputed demand cases.
- Full corridor, Combatentes, Conde Ferreira or Areosa cameras.
- Side-by-side, baseline-only or proposal-only views.
- Shareable view URL containing language, case, camera, time, speed and policy view.
- Selection JSON export, source/result downloads and a link to the detailed experiment.
- Local browser recording of the chosen view to WebM where MediaRecorder/canvas.captureStream is supported. It records from the selected instant to the end of the excerpt; it does not run a new simulation or upload footage.

A localhost/file URL is local to the opening computer. The website must be hosted before a link works for other people.

## Publish or rebuild

Unzip `costa-cabral-proposal-site.zip` and upload all files together to any static website host. Keep both MP4s, posters and supporting files alongside `index.html`. No server-side simulation, database, API key, package install or JavaScript build step is needed for the exported site. Public hosting was not provisioned by this task.

Also retain the nested `vendor/` and `inspection-assets/` folders and `inspection-3d.js`. Three.js is bundled locally with its licence, so no CDN or external map account is required. The 3D module requires HTTP(S), WebGL2 and DecompressionStream; double-clicking the HTML supports the existing 2D mode.

Rebuild from the repository:

```sh
./prototypes/costa-cabral/export-proposal.sh
```

The script installs the pinned project dependencies, captures cached/native replays, renders both MP4s, creates the website and generates its archive. It requires `uv` and `ffmpeg`; if the original run files are absent it first runs the experiment workflow. Use `--skip-video` for text/layout-only site changes; use `--case busy --camera conde --language both` to regenerate standardized films with another scenario/camera.

## Verification

- Both MP4s probed as H.264, 1920 × 1080, 25 fps, exactly 60 seconds. Intro/access/comparison/outcome frames visually inspected.
- Native capture fidelity checked against the source baseline: all 60 completed bus-stop events in the replay period matched exactly.
- Browser checks covered language/video switching, demand/camera changes, timeline advancement and a rendered junction map. No horizontal overflow on desktop or a 390-pixel phone viewport; a shared URL restored the chosen language, case, camera and time.
- A short browser recording produced a valid 1920 × 1080 VP9 WebM, using the selected language, resident-demand case and Conde Ferreira view.
- The archive contains all relative website assets and matches the generated folder contents.

The source-data/model limitations in `FINDINGS.md` and `README.md` still apply, including assumed demand, generated signals, 20-second dwell, local-origin/destination resident proxy, proposal-only lane reduction, unvalidated imported baseline, clipped diversion area and perfect compliance. Costs, safety and actual bus-reliability gains are not validated by this presentation.

## Population and transition explanation

The site adds a separate conditional person-trip calculator and downloadable Markdown/JSON/CSV reports. INE population and IMob/PMUS mode-reference inputs are sourced; door-to-door times, residency/purpose allocation, adoption and capacity remain explicit assumptions. All native corridor replays, the two MP4s and 3D captures have been regenerated after preserving imported baseline lanes and applying lane reduction only to the proposal. The earlier large bus gains are superseded. See [TRANSITION.md](TRANSITION.md).
